These walkthroughs take one person through the four things Avow has to get right. Start with the [agent starter](https://github.com/Avow-Finance/avow/tree/main/examples/starter), which shows limits holding in two minutes. Its sandbox registers your business and pays it test dollars, then your agent books within its authority, Avow refuses a booking past what's left with the lock behind it, and the agent books again.

```bash
npx https://try.testnet.avow.finance/create-avow-agent.tgz my-agent
cd my-agent
npm start
```

The rest run the buyer and supplier quickstarts on one machine against Avow's hosted testnet service, and you play both sides. The buyer quickstart is a business and its agent, and the supplier quickstart is the business the agent books from. Every amount is test tUSD on Tempo's Moderato testnet, so nothing here moves real money.

| Walkthrough | What it shows |
| --- | --- |
| [A kept booking](/docs/walkthroughs/kept-booking) | The supplier accepts, and the whole reserve goes back to the business at its release date |
| [A capped charge](/docs/walkthroughs/capped-charge) | The business cancels late, and the supplier is paid no more than the late-cancellation amount |
| [A disputed charge](/docs/walkthroughs/dispute) | The business contests a charge, the lock pauses it, Avow rules, and the lock pays as ruled |
| [Limits that hold](/docs/walkthroughs/limits) | A booking over the agent's limits is refused with a reason code, which the starter shows first |

## Set up both sides once

Build the quickstarts as the [welcome page](/welcome) shows. From the repository's root folder, make the three businesses.

```bash
export AVOW_FACTORY=0x8fa7177c84BE069df2a51F096ED28d5D661B8283
(cd examples/buyer && node dist/main.js init)
(cd examples/buyer && STATE_DIR=.avow-buyer-spare node dist/main.js init)
(cd examples/supplier && node dist/main.js init)
```

The second buyer is a spare, so a booking that has to be made again doesn't wait on a new registration. Each buyer prints its account and lock, and the supplier prints three addresses. The quickstarts don't register through the sandbox yet, so send all of them, with a name and country for each business, to the person at Avow who invited you to the testnet. Nothing past this point works until Avow has registered them. Avow sends each buyer's account enough test tUSD for three $500 reserves, and sends you each business id. The other settings are the testnet's own, published at https://try.testnet.avow.finance/config.json.

| Setting | Side | What it is |
| --- | --- | --- |
| `AVOW_FACTORY` | Both | Avow's lock factory, the address above |
| `AVOW_API_URL` | Both | Avow's hosted API, `https://api.testnet.avow.finance` |
| `AVOW_TOKEN` | Both | The token reserves are held in |
| `BUYER_BUSINESS_ID` | Buyer | The business id Avow registered the buyer under, with a second one for the spare |
| `AVOW_ARBITER` | Buyer | The arbiter Avow's approvals name |
| `SUPPLIER_BUSINESS_ID` | Supplier | The business id Avow registered the supplier under |
| `AVOW_APPROVAL_KEYS` | Supplier | The address Avow signs authorizations with |

The quickstarts read their settings from the environment, so every terminal needs them. Put them in a file at the repository's root, here called `avow-settings.sh`, and keep it out of version control.

```bash
export AVOW_FACTORY=0x8fa7177c84BE069df2a51F096ED28d5D661B8283
export AVOW_API_URL=https://api.testnet.avow.finance
export AVOW_TOKEN=<from Avow>
export AVOW_ARBITER=<from Avow>
export AVOW_APPROVAL_KEYS=<from Avow>
export BUYER_BUSINESS_ID=<from Avow>
export SUPPLIER_BUSINESS_ID=<from Avow>
export SUPPLIER_URL=http://localhost:8790
```

The walkthroughs use two kinds of terminal. A supplier terminal works in `examples/supplier`, and a buyer terminal works in `examples/buyer`, each with the settings loaded. Open the first supplier terminal, start the supplier and leave it running. The buyer reaches it at `SUPPLIER_URL`.

```bash
cd examples/supplier
source ../../avow-settings.sh
node dist/main.js serve
```

Then open a buyer terminal and authorize the agent. Keep the default limits, which let the agent hold three $500 bookings at once.

```bash
cd examples/buyer
source ../../avow-settings.sh
node dist/main.js enroll
```

Every later command says which kind of terminal it runs in. A second terminal of either kind opens the same way.

## The order that fits an hour

A booking with the default window takes 42 minutes from `book` to its release, and a dispute takes about as long, so the walkthroughs run side by side. Times are from the first `book`.

| Time | Buyer | Supplier |
| --- | --- | --- |
| 0:00 | Books the dispute's booking, then the capped charge's | Accepts each booking on its own |
| 0:02 | Books the kept booking in a second terminal, and leaves it waiting for the release | Accepts it |
| 0:04 | Tries the two bookings in [Limits that hold](/docs/walkthroughs/limits), which are refused | Nothing |
| 0:08 | Cancels the dispute's booking and the capped charge's booking, now that free cancellation has ended | Nothing |
| 0:09 | Nothing | Reports a late cancellation on both, and Avow confirms each within five minutes |
| About 0:13 | Contests the dispute's charge as soon as Avow confirms it, since the contest window lasts ten minutes | Nothing |
| About 0:25 | Nothing | The capped charge pays $250 once its contest window has closed |
| 0:44 | The kept booking's reserve comes back | Nothing |
| By 0:50 | Avow rules on the dispute within 30 minutes of the pause, by about 0:43, and the lock pays five minutes after the ruling | The ruling's share arrives |

Name each booking by the commitment id `book` printed, since `cancel` and `contest` otherwise take the latest booking. The agent's key can move $1,500 a day at the default limits, which is exactly these three reserves. If a booking has to be made again the same day, switch to the spare in a buyer terminal with `export STATE_DIR=.avow-buyer-spare BUYER_BUSINESS_ID=<the spare's id>`, run `enroll` once, and book from there.

## Testnet timing

Avow's testnet locks run on minutes where a live lock would run on days, so a whole dispute fits in an hour.

| Step | On testnet |
| --- | --- |
| Free cancellation ends | 6 minutes after `book`, with the default window |
| A no-show can be reported | 14 minutes after `book` |
| The reserve is released, and the last charge can be reported | 42 minutes after `book` |
| Avow confirms or refers a report | Within 5 minutes of the report |
| The business can contest a confirmed charge | For 10 minutes after Avow confirms it |
| Avow rules on a paused charge | Within 30 minutes of the pause |
| The lock pays a ruling | 5 minutes after Avow posts it |
| The arbiter can rule | Until 90 minutes after the pause, when the lock splits a charge nobody ruled on |

Every transaction is on the [Moderato explorer](https://explore.testnet.tempo.xyz). Search for your lock to follow each booking's reserve, report, contest and payment.
